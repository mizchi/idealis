# Idealis 言語の設計

`.ideal` は、ドメインで考える望ましい振る舞いを記述するソースファイル。名前にはプラトンのイデアのニュアンスがある。用語、状態、操作、守るべき性質をつなぎ、形式検査と実装照合で同じドメインの名前を使えるようにする。

## モデルと検査の境界

| 責務       | 所有するもの                                               | 現在の置き場                                            |
| ---------- | ---------------------------------------------------------- | ------------------------------------------------------- |
| 構文       | `.ideal` の表記、構文木、ソース位置                        | `idealis-syntax`                                        |
| モデル     | 名前解決、型検査、検査済みの宣言・式・性質                 | `idealis-syntax` の `Model` と `CheckedModel`           |
| 意味論     | 初期状態、操作の有効性、同時更新、スコープ逸脱             | `idealis_semantics::reference`                          |
| 仕様の対応 | ユビキタス言語、自然言語の規則、モデルの性質と実装への参照 | `idealis-spec`。現在の文書入力は Pkl                    |
| 検査と照合 | 検査器の選択、予算、判定、反例、実装観測と ITF             | `rcheck`、各検査器、`idealis-core` のポータブル実行 API |

今回の分離では `idealis-syntax` を `idealis-semantics` が参照する。型生成と Alloy・TLA+ への変換は `rmodel` に置き、従来の API から新しい型と評価器を再公開する。`idealis-core` はポータブルな実行 API を持つ。今の `FiniteModel` は、状態と遷移を列挙した実行・再生用の形式。型検査済みの宣言モデルから生成できる形として位置づける。規則と用語は安定した ID で参照し、形式的な性質、検査結果、実装上の観測をたどれるようにする。自然言語の規則を `.ideal` に書く構文は設計中。

意味論は操作をしたとき何が起こるかを決める。探索予算、検査器の対応範囲、反例を発見したかは検査結果に記録する。各バックエンドは検査済みモデルを受け取り、結果と証拠は元のモデルで照合できるようにする。[核の意味論](kernel-semantics.md) · [検査器の契約](backend-contract.md)

## 再利用できる実装

Idealis が接続層を通して外部形式やエンジンを利用する。TLA+ のパーサー、コンパイラー、探索器や Alloy・SMT-LIB の実装は、Idealis 固有の用語や `.ideal` への依存を持たずに単独で使えるようにする。

| 名前                                               | 位置づけ                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------- |
| `rtla`・`rtla-compiler`・`rtlc`・`ralloy`・`rusmt` | 他の形式に対応する再利用可能な Rust 実装                                   |
| `idealis-spec`                                     | Idealis の用語、規則、性質、実装の対応                                     |
| `rprob`                                            | ProB に着想を得た Idealis 向け探索器。将来の名前の候補は `idealis-explore` |
| `rquint`                                           | Quint IR から TLA+ への変換器。独立配布時の名前の候補は `quint-to-tla`     |
| `rcheck`                                           | Idealis の検査・照合 CLI。将来の入口の候補は `idealis check`               |

## 移行

- 新しいソースは `.ideal` を使う。単独ファイルと、既存の `.rmodel.json`・`.component.json` に含まれる断片を読める。`.model` も引き続き読める。
- 仕様リンクのクレートは `idealis-spec`。Pkl の入力形式、規則 ID、既存の照合リビジョンのハッシュ方式は引き続き利用できる。
- TLA+ ソースの読み込みとバンドルのコンパイルは `rtla-compiler` が担当する。既存の `idealis_core::compile_tla` と Wasm リクエストは、その API を呼ぶ入口として使える。
- `rcheck` はソースと JSON IR の両方を `idealis-syntax` が所有する `CheckedModel` に通す。従来の `rmodel::CheckedModel` は同じ型の再公開。`rprob` と `idealis-spec` のライブラリは新しい両 crate を直接使う。
- crate の分離を先に行い、既存の評価規則を精査する作業は次の段階とする。分離の検証では IR、生成物、判定と反例を照合する。
