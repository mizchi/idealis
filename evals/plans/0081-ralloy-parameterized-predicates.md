# 0081: ralloyの引数付きpred/fun

[0078](0078-ralloy-alloy-oracle.md)の4段目。今のralloyは、引数のない`pred`だけを扱う。

## 変更

- `pred P[x, y: A, z: B] { ... }`と`fun f[x: A]: 型 { 式 }`、引数のない`fun f: 型 { 式 }`。引数の宣言は`[]`で書き、`disj`を付けられる。引数の多重度は既定の`one`だけを扱い、`set`などは未対応として拒否する。戻り値の型は構文として読むだけで、評価には使わない。
- 呼び出しは`P[a, b]`と、receiverを前に置く`a.P[b]`、`p.f`（`f[p]`と同じ）。名前がpred/funでなければ`e[a]`はbox joinで`a.e`、`e[a, b]`は`b.(a.e)`。
- 呼び出しは、引数を呼び出し側の環境で評価し、本体を引数だけの環境（呼び出し側の局所変数は見えない）で評価する。引数の多重度は呼び出し時には検査しない（`out[out[x]]`のように集合を渡せる）。
- `run P`で`P`に引数がある時は、`some x, y: A | P[x, y]`として解く（`disj`の引数は`some disj`）。
- 再帰は今までどおり拒否する。

## 正しさ（結果を見る前に固定）

- group `predicates`（5モデル・23 command、記録済み）がAlloyの答えと全一致すること。
- `core`・`nary`・`hierarchy`の再生が0080と同じ状態のままであること（`nary`の1件だけが予算切れ）。
- 人工故障: 引数を逆順に束縛する、本体に呼び出し側の局所変数を見せて引数を束縛しない、引数付きの`run`を`all`で量化する、`disj`の引数を無視する、の4件を再生テストが検出すること。
