# 0126 rprob の探索プロファイルと最適化

4×4の辺探索をmacOSの `sample` で4秒計測した。スタック先頭には述語評価991標本、項評価797標本、ハッシュ書き込み283標本があった。準備後の探索を、状態の保存、式の評価、候補走査の順で個別に変更・比較する。

1. 単一スロットは値そのものをFIFOへ入れる。総 tuple が16以下で予算がビットマップのワード数以上なら、合法値が占め得るビット位置を詰めて既訪問を直接添字にする。他はハッシュ集合で扱う。
2. 定数との集合演算、定数一要素からの像、定数を含む述語を lowering で特殊化する。同じ式の空集合とアリティの規則を持つ。
3. 大きな候補領域で添字復元にかかるコストを調べ、連続ビット位置と二冪基数を活かす。異なる宣言順と疎な配置、関数の候補数は従来の列挙と突き合わせる。

各段の release バイナリを保存し、前段との判定全文一致を測定前に確かめる。Hyperfine のウォームアップ1回・5標本で壁時計、命令数、ピークRSSを測る。入力は4×4の密な辺探索（3回）、権限モデル（20回）、18 atomの疎な集合探索（3回）、2スロットの探索（3回）、6×6の全関数で予算46,658（40回）。候補走査の確認用に、全18 atom集合候補を検査する疎な集合探索と6×6全関数を使う。すべて準備済み。さらに候補4領域・予算1の都度準備で既知の改善を守る。主対象に改善があり他の軸の退行が目立たなければ残す。退行は計測値と合わせて記録する。

回帰では参照との判定、深さ、宣言違反、操作の到達、空と予算切れの差を確認する。とくに既出の状態へ戻る遷移でも遷移性質を評価すること、配置に穴がある異なる状態を混同しないこと、ビットマップの適用境界で予算が変わらないことを確認する。

候補走査は、連続する単項ビットをシフトで復元し、二項の行選択を繰り上がりで更新する。後者は二冪に限らず走査中の除算を省く。式の最適化まで測った後、2スロットにも固定長キーを使う試行を追加する。対象は同じ6負荷で、2スロットの命令数とRSSを重点的に見る。

固定長の状態保存後に権限モデルを再プロファイルした。項・述語評価がスタック先頭に残るため、状態を読まない操作ガードを構成ごとに一度だけ評価する試行を追加する。初期状態がなく、到達状態を消費できない場合は、構成上ガードを通るだけでは操作到達として数えない。同じ6負荷で測り、権限モデルを主対象にする。

5段目の後、密な辺探索のスタック先頭に宣言検査148標本とメモリコピー94標本が残った。6段目で `set` の多重度検査を即時に通し、全スロットを代入する操作では前状態のコピーを省く。予算が初期候補の検査で尽きた時点ではガードも準備しない。部分代入、並行代入、宣言違反、予算境界を既存の比較と追加の回帰で確認し、同じ6負荷で5段目と比較する。
