# 0084: ralloyの対称性の除去を探索の途中で行う

[0083](0083-ralloy-symmetry.md)で残った2つの課題を扱う。mizchiの指示で、0079から残る小さいcaseの固定費は、目立つ問題にならない限り扱わない。

1. `nary`の`CompositionHolds`（`sig Q { r: P -> P }`をscope 3でcheck）が、work予算5000万で予算切れになる。葉が約1.34億あり、0083の方法（葉に着いてから評価前に除く）では、列挙だけで予算を超える。さらに、2列以上のfieldがあるcommandでは除去自体をしていない。
2. 0083では、subset sigへの所属が同じatomだけを入れ替えの対象にした。人工故障の検査で、subset sigの所属を無視しても答えが変わらないことが分かった。subset sigは探索で選ぶ変数なので、所属だけが違うatom同士も入れ替えられる。

## 変更

- 入れ替えの対象: Int atomでなく、subset sig以外のすべてのsigへの所属が同じ、隣り合うatomの組。
- 2列以上のfield: 互換でtuple空間の各tupleのatomを入れ替えた時の、tupleの番号の置換を前計算し、maskのbitを置換する。0083の除外をやめる。
- 途中での判定: 辞書順は0083と同じ（fieldの順、その中はownerのatomの順に、各行の値を並べた列）。slotを割り当てるたびに、互換ごとに、先頭から等しいと分かった位置を進める。入れ替え先の行がまだ割り当てられていない位置で止める。入れ替えた値が小さい位置が見つかれば、その枝を刈る。大きい位置が見つかれば、その互換は以後判定しない。戻る時は状態を元に戻す。葉ではすべての位置が決まるので、0083の葉での判定は不要になり、取り除く。
- 各軌道の辞書順で最小の代表は、どの互換でも刈られずに残る。statusは変わらない。返すinstanceと`stats`は変わる。

## 正しさ（結果を見る前に固定）

- 5 groupの再生がAlloyと一致すること。`CompositionHolds`が解けた場合は、pendingの一覧から外し、その答え（反例なし）がAlloyと一致すること。解けない場合は、必要なworkを予算を外して測り、記録する。
- 人工故障: 2列以上のfieldでtupleの置換をしない、subset sig以外のsigの所属も無視する、戻る時に判定の状態を戻さない、入れ替え先の行を自分自身にする、の4件を再生テストが検出すること。

## 速度（結果を見る前に固定）

0083aのcandidateの保存binaryをbaselineとして、`core`の13ケースを交互の順に測る。13ケースすべてで、両組のcandidate/baselineの比が1.1以下。超えたケースは後退として記録し、閾値を変えない。
