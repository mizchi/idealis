# 0114 rmodel の核と移植先を再検証する

先に判定基準を固定する。型検査と IR の往復、独立した言語アダプタ、検査器実行の三段階を分ける。IR 往復では意味だけでなく正規化 JSON の一致を求める。検査では、既知の期待と参照評価器の両方と照合する。未対応、空、境界逸脱、予算切れ、プロセス失敗、深さの違いを独立に記録する。TLC に渡す TLA+ は rmodel の既存の emitter を使い、Alloy Analyzer は対応モデルの Alloy 出力を使う。Alloy の有界結果から完全性を結論しない。

- 新しい二題材は初期残高2・整数0〜4の出金と、3ノード単一任期の Raft 選挙。正常版で安全性と到達例がそろい、故障対照では出金で残高を消し、選挙で投票済みガードを外す。変更の前後を同じ検査器に入力する。
- 対照として構造的な ACL、矛盾した初期状態、整数範囲からの逸脱を使い、意味の不一致と実行上の制約を区別する。
- Pkl から既存の正常版と二つの故障を再生成する。Quint は公式の言語仕様と既存の受け口を確認し、コードが未実装の変換は未測定とする。
- 分散システムへの拡張を調べるため、順序と重複を持つログ、三項関係、公平性つきの進行性を構文・IR の両方で表現できるか調べる。手作業の有限展開が可能な項目は、型や観測が保持されるかまで別に評価する。
- 生成した Rust、TypeScript、Go の照合では実装側と参照模型の操作ロジックは独立。既存テストを再実行する。結果が合うだけで完全な双方向変換や任意精度の実装互換性は主張しない。

公平性の対照は実行前に固定する。TLC で同じ一変数の配信モデルを使い、常に選べる待機と配信を持つ場合に、弱公平性の有無だけを切り替えて `<> delivered` を比べる。rmodel の到達可能性と進行性の違いを測る。64ビット上限での加算と、別の値型に同じフィールド名を持たせる試みは、探索的な実行で見つけた。確認ランではその入力を固定して再生する。
