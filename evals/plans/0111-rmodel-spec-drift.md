# 0111 自然言語の仕様から文法の検査を回す

文法の変更理由は意思決定ログに残し、守る規則は自然言語で先に書く。rmodel で判定できる条件を規則から参照し、コードを動かさないと確認できない条件は実装の検査を参照する。今回の対照は既存の `action` と、`behavior` による同じ状態遷移。

- 正常版は、変数を入れ替え、代入しない変数を保持する。条件が外れれば次の遷移を起こさない。
- 採用判断は一件の変更を扱う。意味の一致とゴールの改善を両方必要とし、片方を省くモデルで各規則が破れることを確かめる。
- rspec は規則の参照と rmodel の判定を照合する。Jev は自然言語の規則とモデルの意味を比較する。判定を取得できなければ未検査として記録する。
- 自然言語だけがずれた対照として、モデルを固定し「意味に差があってもゴールが改善すれば採用できる」と書き換える。通常の規則は支持、書き換えた規則は矛盾を期待する。
- `behavior` の読みやすさは別の測定で判断する。この周回では規則・モデル・実装検査を結びつけ、初回の drift check の結果を意思決定ログに追記する。
