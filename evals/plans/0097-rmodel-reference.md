# 0097: rmodelの参照評価器と、写し方の差分テスト

mizchiの方針: 形式ツールを束ねる自前の記述体系を作る。各検査器が別々の意味論を持つ状態をやめ、意味論の正本を1か所に置く。決めたこと:

- 意味論の正本は参照評価器（Rustで小さいscopeを全列挙する）。文書は評価器の説明として書く。
- 整数は数学の整数。有界な検査器が範囲を超えたら、判定を未確定にする（0096の規則を核の規則にする）。
- 最初は、今のrmodelの範囲で参照評価器を作り、既存の2つの写し方（Alloy・TLA+）を差分テストにかけて、意味のずれを機械的に洗い出す。核のIRへの切り替えは次の段階。

## 参照評価器の意味論（今のrmodelの範囲）

- sortはscopeでちょうどの大きさのatomの集合。enumは名前の付いた、ちょうど1つずつのatom。sortとenumのatomはすべて互いに異なる。
- 設定: すべての`rel`への、型（定義域の部分集合）と多重度を満たす割り当てのうち、`fact`を満たすもの。
- 状態: すべての`var`への、型と多重度を満たす割り当て。初期状態は、それに加えて`init`を満たすもの。
- 遷移: action・引数の値の組ごとに、現在の状態で条件が成り立つとき、代入の右辺を現在の状態で評価した値を次の状態とする。代入しないvarは変わらない。次の状態が型と多重度を満たさない遷移は起きない。
- `#`は数学の整数（桁が回らない）。
- `invariant`はある設定のある到達できる状態で偽なら破れる。`reachable`はある設定のある到達できる状態で真なら到達できる。違反・到達の深さは、初期状態からの最短の遷移の数。
- 予算（評価した状態の数）を超えたら、その判定は未確定。完全に探索したときだけ成り立つ・到達できないと答える。

## 差分テスト

- engine: 参照評価器（完全）、rtlc（TLA+の写し方、完全）、ralloyのSAT（Alloyの写し方、stepsで有界）。
- 比較の規則: 参照評価器とrtlcは判定が一致すること。SATは、参照評価器の違反・到達の深さがsteps-1以下なら一致すること。成り立つ・到達できないときもSATは一致すること（有界でも反例がないので一致するはず）。深さがsteps以上のcaseは数えて報告する。
- corpus: `fixtures/rmodel/*.model`、`spec/models/*.model`、rmodelのテストのモデル。0091・0093・0094の期待とも一致すること。
- 生成したモデル: 型の合ったrmodelのモデルを乱数で生成する（sort 1〜2個・大きさ1〜3、enum 0〜1個、静的な関係0〜2個、var 1〜2個、fact・init・action 1〜3個、check 2個、式の深さ3まで）。開発用のseedは0〜299、確認用のseedは1000〜1299（開発の結果を見た後に1回だけ使う）。
- 不一致はすべて記録し、1件ずつ、どのengineがこの意味論と違うかを調べて分ける（写し方の誤り、検査器の誤り、参照評価器の誤り、意味論が決まっていない）。不一致を消すために比較の規則を後から緩めない。

## 範囲外

- 核のIRへの切り替え、検査器が核のIRを直接受け取ること。
- 時相の性質、bool・record・mapなどの値。
