# 0096: SATの経路で整数の桁あふれを検出し、判定を未確定にする

[0095](0095-quint-sat.md)のSATの経路は、状態に依存する算術がbit幅を超えると、ralloyの2の補数で黙って桁が回る。存在しない反例を報告しうる正しさの穴なので、検出して判定を未確定にする。

## 変更

- `rquint::to_alloy`は、状態に依存する足し算・引き算・符号反転ごとに、桁あふれしない条件を作る。足し算`plus[a, b]`は「aとbの符号が同じなら、結果の符号も同じ」、引き算は「aとbの符号が違うなら、結果の符号はaと同じ」、符号反転は「aが最小値でない」。
- 条件は専用のcommand `c_overflow`（`check { always { 条件 } }`、同じscope）として出す。遷移の中の算術は、その状態から見た値で条件を作る。
- 状態に依存する掛け算は、SATの経路で拒否する（ralloyのSATは`div`を持たず、桁あふれを正確に書けないため）。
- 検査する側は、`c_overflow`に反例があれば、他のcommandの判定を未確定として扱う。

## 正しさ（結果を見る前に固定）

- `fixtures/quint-ir/Overflow.qnt`（0から3ずつ増える）: 8 stepsで21に達し5 bitを超える。
  - `c_overflow`は反例を持つ（桁あふれを検出する）。
  - 判定は`nonnegative`・`small`とも未確定として報告する。
  - 対照として、guardを使わずに`c_nonnegative`だけを解くと反例が出る（桁あふれによる偽の反例）。rtlc（深さ8の上限）は`nonnegative`に違反を見つけず、`small`には違反を見つける。
- 0095の10件では、`c_overflow`に反例がなく、判定は0095と同じ。
- 人工故障: 足し算の条件を落とす（`c_overflow`が常に成り立つ）を、Overflowの検査が検出すること。
- 掛け算を含むモデル（状態に依存する`count * 2`）は拒否されること。

## 範囲外

- 桁あふれを避けるためにbit幅を自動で選ぶこと（ralloyは5 bitまで）。
- 掛け算・割り算の桁あふれの符号化。
