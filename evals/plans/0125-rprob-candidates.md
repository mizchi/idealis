# 0125 ProB 系の試作を候補列挙から改善する

rprob は ProB に着想を得た試作と明記し、対応範囲、空・予算切れ、参照との差分、測定条件を一緒に報告する。改善候補は、全候補の事前確保を、小さい選択表と必要時の列挙に置き換えること。二項関係の one / lone は行ごとの合法な選択から作る。候補順、予算、判定と最短深さは従来対応範囲で維持する。

比較は同じ release ハーネスの変更前後を使用する。各コマンドは開始前に判定の一致を確認し、1回ウォームアップ・5標本で壁時計・命令数・ピーク RSS を測る。軸は①4個の20 atom集合・予算1・毎回準備、②4×4全関数・候補を走査・毎回準備、③4×4密な辺探索・準備再利用、④既存の権限モデル・準備再利用。①②の削減と③④の目立つ退行を確認する。従来の参照評価器が拒否する6×6の全関数は、独立に計算した6⁶個の初期候補と予算境界で検査する。
