# 0118 発送の仕様と3言語の再生

発送後は発送済みのままで、追跡方法を保存する。自然言語の規則 SHIPMENT-TRACKING を既存の ShippedStays にリンクする。初期状態は未発送、設定は空、追跡方法は Post と Courier の2値。

| 変更箇所      | 対照                                               | 期待する結果                                                                                        |
| ------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 規則のリンク  | ShippedStays の参照名だけ変更                      | rspec が参照を拒否する                                                                              |
| 自然言語      | 発送済みを維持しつつ、追跡方法の変更を明示的に許可 | リンク検査は通り、Jev は意味の食い違いを報告する。判定を取得できなければ未計測                      |
| rmodel の更新 | 確認時に追跡方法を Post に変える                   | ShippedStays が2操作目で破れ、トレース生成も拒否する                                                |
| 各実装の更新  | 同じ上書きを Rust、TypeScript、Go に個別に入れる   | 正常実装は全スナップショット一致。Courier は確認時に初めてずれ、Post は変更なしの対照として一致する |

ITF の入力は各追跡方法で発送して確認する2列とする。初期状態から各操作後までの期待値を rmodel の参照評価器で生成し、固定 fixture に保存する。SUT は生成インターフェースを実装し、同じ fixture を再生する。TypeScript の fast-check と Go の fuzz seed にも固定の Courier 列を含める。意味判定は仕様を同義に言い換えた対照も用意し、文章が変わったこと自体を矛盾に数えない。
