# 0091: 構造と振る舞いを1つのモデルで書く言語の核（rmodel）

[plan](../plans/0091-rmodel-language.md)のとおり、静的な関係（設定）・状態の関係・暗黙のframeを持つactionを1つのモデルで書く言語の核`crates/rmodel`を作った。同じモデルを、独立した2つの写し方でAlloy 6とTLA+へ写す。

- **一致**: 5モデル・20 checkで、ralloyのSAT（有界）・rtlc（完全）・Alloy 6.2.0・TLC 1.8.0の4つの判定が、モデルと同時に書いた期待とすべて一致した。明示状態が違反・到達を見つけた深さは、すべてstepsの内側。
- **設定の空間**: 権限モデル（静的な付与と、状態の閲覧）では、SATが1 check 0.3〜1.7 ms、明示状態は300〜763 ms。明示状態は設定の候補をInitで列挙する（2,822〜20,368状態）。振る舞いだけの小さいモデルでは両者は同程度で、明示状態の方が速いものもある。
- **依存**: crateは依存なしで、engineは呼ぶ側が選ぶ。

## 人工故障

| 故障                                  | 検出                                              |
| ------------------------------------- | ------------------------------------------------- |
| Alloyで暗黙のframeを落とす            | SATの判定（`sessions/Capacity`）                  |
| TLA+で暗黙のframeを落とす             | rtlcが未代入の変数として拒否                      |
| TLA+でvarの多重度を初期状態だけにする | 未検出→corpus追加後に検出（`declared/OneHolder`） |
| TLA+でjoinの向きを逆にする            | rtlcが型の誤りとして拒否                          |
| Alloyでjoinの向きを逆にする           | SATの判定（`declared/BothHeld`）                  |

多重度の故障は最初のcorpus（4モデル・17 check）で検出しなかった。actionがすべてguardで多重度を守っていて、宣言が遷移を止める場面がなかったため。結果を見た後に、宣言だけが遷移を止める`declared.model`（3 check）を加えた。期待する判定は、そのモデルを実行する前に書いた（`expected.json`の`added`）。

最初の試行で、Alloy側のjoinの故障は置換が文字列の中のコメントになり、何も変えていなかった。左右を入れ替える故障に直して入れ直した。

## 計画からの差

- planは4モデル・17 checkだったが、上の理由で5モデル・20 checkになった。
- planにない二項同士のjoinと積を、`composed_relations_agree`で両方の写し方について確かめた（corpusは使わない）。
- rtlcは`\X`に対応しないため、積は`{<<x, y>> : x \in A, y \in B}`、二項同士のjoinは`UNION`で書いた。
