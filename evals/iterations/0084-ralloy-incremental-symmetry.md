# 0084: ralloyの対称性の除去を探索の途中で行う

[plan](../plans/0084-ralloy-incremental-symmetry.md)のとおり、対称性の判定を葉から探索の途中へ移した。2列以上のfieldとsubset sigにも広げた。

- **`CompositionHolds`**: 予算内では解けず、pendingのまま。予算を外すと、評価まで進む候補は約1.3億から886万（約15分の1）になり、Alloyと同じ「反例なし」に至った。ただし必要なworkは25.6億（release 51秒）で、予算5000万の約51倍。
- **速度**: 0084も追記の0084aも`hold`。大きい探索は少し速くなったが、数µsのケースが最大1.22倍になった。
- **方針**: mizchiの指示（小さいcaseの固定費は、目立つ問題にならない限り扱わない）に従い、これ以上は追わない。

## 変更

- 互換ごとに、slotの順で先頭から等しいと分かった位置を持つ。slotを割り当てるたびに比較を進める。
  - 入れ替えた値が小さければ、その枝を刈る。大きければ、その互換は以後判定しない。
  - 入れ替え先の行がまだ割り当てられていない位置で止まる。
  - 戻る時はundo logで状態を元に戻す。
- 辞書順は0083と同じ。各軌道の最小の代表は残るので、statusは変わらない。
- 2列以上のfield: 互換によるtuple空間の置換を前計算し、maskのbitを置換する。
- subset sig: fieldのownerにも列にもならないsubset sigへの所属は、atomを区別しない。subset sigは探索で選ぶ変数なので、入れ替えても解は解に移る。
- 0084a:
  - atomを区別するsetの判定を、解析ごとに1回だけ計算する。
  - slotの位置を固定長の表で引く。
  - 入れ替えられる組がないworldでは、何も作らない。

## 正しさ

- 5 group・174 commandのうち173でAlloyと一致した。`CompositionHolds`は予算切れのまま。
- 新しい単体テストを2つ加えた。
  - 刈る版と、刈らずに葉で全体を比べる版（0083の判定）が、corpusの全commandで、評価まで進む候補の並びまで完全に一致する。
  - 2列以上のfieldの`image`が、各tupleのatomを直接入れ替えた結果と、9 tupleの全maskで一致する。

| 故障                                  | 最初の検査                                   | テスト追加後 |
| ------------------------------------- | -------------------------------------------- | ------------ |
| subset sig以外のsigへの所属も無視する | 検出                                         | 検出         |
| 入れ替え先の行を自分自身にする        | 検出                                         | 検出         |
| 戻る時に判定の状態を戻さない          | 検出されず                                   | 検出         |
| 2列以上のfieldでtupleの置換をしない   | 未実施（置換対象の文字列が見つからなかった） | 検出         |

「状態を戻さない」故障は、Alloyの再生では答えが変わらず、見逃した。刈る版と葉で比べる版の差分テストを加えて検出した。「置換をしない」故障は、両方の版が同じ置換を使うため差分テストでは見えない。tupleを直接入れ替える定義との比較を加えて検出した。

Rust・TS・Chromium・`just check`・`wasm-test`・`package`・`evaluate`・`replay-evaluation`が通った。

## 残り

`CompositionHolds`を予算内で解くには、さらに約50倍のworkの削減が必要。総当たりの枠組みでは、対称性の除去だけでは届かない。ownerごとに独立した性質の分解や、SAT符号化のような別の方法が要る。
