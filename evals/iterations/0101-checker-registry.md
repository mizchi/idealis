# 0101: 検査器の共通の枠と、1つの入口

[plan](../plans/0101-checker-registry.md)のとおり、crate `rcheck`を作った。rmodelのモデルの問い（`invariant`・`reachable`・`Declarations`）に、登録した検査器が宣言した範囲で答え、用語集の語で返す。

```sh
rcheck model.model                    # auto: completeで答える最初の検査器
rcheck model.model --checker all      # 全検査器と食い違い
rcheck model.model --checker sat --question Safe
```

- **宣言**: 参照評価器は関係の取りうるtupleが20以下ならcomplete（`rmodel::reference::enumerable`）、明示状態（rtlc）はcomplete、SAT（ralloy）はstepsまでのbounded。
- **答え**: 判定（成り立つ・破れる・到達できる・到達できない・空・未確定・エラー）、範囲、検査器、最短の深さ。boundedの成り立つ・到達できない、未確定、エラーは`definite`でない。
- **食い違い**: 決まった2つの答えの判定が違うとき。ただし、boundedの否定の答えは、bound以上の深さの反例や、空との区別がつかない到達できない（SATのrun）とは食い違わない。差分テストの規則と同じ。

## 正しさ

| plan の条件                                                                    | 結果                                                                        |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| corpusの全claimで`auto`がclaimと一致し、`all`が食い違わない                    | 32 claimすべて。`auto`はすべて参照評価器を選んだ                            |
| 参照評価器が対応しない大きさで`auto`が明示状態へ移り、予算切れを未確定と答える | 移った。答えは未確定（下記）                                                |
| SATの反例なしをboundedとして返す                                               | 返した（深さ3の反例を、steps 2のSATは成り立つと答え、食い違いにはならない） |
| 存在しないcheck・検査器はエラー                                                | エラー                                                                      |

参照評価器が対応しない大きさのモデル（`A -> set A`、A = 5、tuple 25）では、明示状態も答えを出せなかった。TLA+の写し方は初期状態を`r \in SUBSET D_r`（2^25通り）で数え上げ、既定の予算で5分33秒かけて予算が尽きた（未確定）。テストを書いたときは破れる（深さ2）と期待していたが、実測に合わせ「未確定と答え、成り立つと言わない」を確かめる形に直した。SATはstepsの中で反例を見つける。参照評価器と明示状態は、同じ大きさのところで止まる。

## 結果を見た後に直したこと

0100の差分テストで、2つのseedがcrashした（5141はメモリ15GBでSIGKILL、6130は600秒の上限）。どちらも参照評価器が原因で、rcheckの「予算が尽きたら未確定と答える」を破っていた。

- 設定の組み合わせ（`product`）をすべてメモリに作ってから回していた。1つずつ作るiteratorにした。5141（約2億通り）は、60秒・32MBで、明示状態と同じ判定（violated・reachable・unknown）を返した。
- 予算に、到達した状態だけを数えていた。調べた設定と初期状態の候補も数えるようにした。回帰テスト（設定が530万通り・初期状態の候補が6.5万通りのモデル）は、直す前は56秒かかって失敗し、直した後は7秒で未確定を返す。明示状態は、同じモデルで小さい予算なら8秒以内に未確定を返した。

予算の数え方が変わったので、0097〜0100の記録は、その時点の参照評価器で再現する。

## 範囲外のまま

- 明示状態とSATのwitness（trace）を、核の値へ戻して参照評価器で検査し直すこと。
- `auto`で、選んだ検査器が未確定のときに次の検査器へ移ること。上の大きなモデルでは、SATなら答えられた。
- TLA+の初期状態を数え上げない写し方、メモリの上限。
