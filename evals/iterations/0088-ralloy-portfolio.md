# 0088: 総当たりとSATのportfolio

[plan](../plans/0088-ralloy-portfolio.md)のとおり、総当たりを5000 workで先に走らせ、終わらなければ残りの予算でSATへ切り替えるportfolioを実装した。

- **正しさ**: すべて通った。
- **速度**: 2回の測定がどちらも、関係のないプロセスの負荷（負荷平均8〜22）の中で行われた。判定は`hold`で、変更はrevertした。境界は24 bitのまま。
- **残り**: 静かなホストで測り直せば、判定をやり直せる。

## 実装

`search::portfolio`。SATで扱えるモデル（`div`・`rem`を含まない）では、まず総当たりをwork予算`min(5000, 全体)`で解く。予算切れなら、残りの予算でSATで解き、`work`は両方の合計にする。

5000 workは、結果を見る前に0087の数字から決めた。SATの小さい問題の固定費が約100 µs、総当たりは約50 work/µsで、その積にあたる。

## 正しさ

- 5 groupの再生（178 command）がAlloyと一致した。
- 予算の単体テスト:
  - 総当たりが最初の予算で終わらないcheckで、全体の予算を5001、15000、5000万にしても、返す`work`が予算を超えない。
  - 全体の予算が5000以下なら総当たりだけで解き、`unknown`のまま返す。
- 人工故障2件（SATへ全体の予算を渡す、予算切れでもSATへ切り替えない）をどちらも検出した。
- Rust・TS・Chromium・`just check`・`wasm-test`・`package`・`evaluate`・`replay-evaluation`が通った。

## 速度

| 比較                                                 | 負荷平均（1分） | 扱い                                               |
| ---------------------------------------------------- | --------------- | -------------------------------------------------- |
| [0088](../runs/0088-ralloy-comparison/result.json)   | 8.1〜22.1       | 記録のみ（比較の計算前に、判定に使わないと決めた） |
| [0088a](../runs/0088a-ralloy-comparison/result.json) | 4.2〜17.9       | `hold`                                             |

0088では、関係のないnodeプロセスで負荷平均が22まで上がっていた。0079〜0087の測定時（3〜8）より桁違いに高い。0088の比較を計算する前に、追記の[0088a](../plans/0088a-ralloy-portfolio-remeasure.md)で、判定は負荷の下がった時の1組だけで行うと決めた。

0088の閾値の追加にも失敗していた。目印にした0087の行が、0087のrevertで消えていたため。0088aで足した。

0088aは、1分の負荷平均が5を下回るのを待って始めた（開始時4.18）。しかし測定中に9〜11へ戻った。手順の穴は、開始時の1分の値しか見ていなかったこと。

結果は判定に使える状態ではなかった。

- 同じbaselineのbinaryで、`core-set-algebra`は以前の約33 msに対して99 msだった。
- 開発組と確認組で比が逆に振れた。`core-preds`は0.335/1.562、`core-quantifiers`は0.359/1.434、`core-dag-closure`は3.509/0.798。

8ケースが閾値1.1を超えて`hold`。planは再測定を1組までと決めていたので、portfolioをrevertした。

向きが安定していたのは`core-set-algebra`だけだった（0.003/0.006）。総当たりでは数え尽くしに時間のかかるcheckがSATに回ったため。ただし、これだけで採用する根拠にはしない。
