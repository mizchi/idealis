# 0115 整数の範囲、Nat、処理前の検証

[計画](../plans/0115-nat-validation.md)に沿い、参照評価器の算術と TLA+ への変換に別々の表現上限を置いた。論理式、アクションのガードと更新、record の射影を含めて保守的に見積もる。参照評価器の上限を超えうる式は型検査で拒否し、TLA+ の上限だけを超える場合は TLA+ lowering の対象外とする。判定にガードから得られる範囲の絞り込みは使わない。

- 0114 で成立と判定していた `i64::MAX + 1` は、ソースと同じ型検査を通す IR の入口で拒否する。加算の前に record のリテラルから上限の値を読み出す例も拒否した。
- `2147483647 + 1` は参照評価器では正確に評価し、有限の列挙範囲を出たと判定する。TLA+ lowering は数値表現の上限を理由に断る。
- `Nat` は0以上の整数。Nat の値と Int を比較できる。Nat の変数・record フィールドを負の値に更新する対照では、参照評価器と rtlc が範囲逸脱を確認し、安全性を `unknown` とした。
- Nat の出金モデルでは残高の上限を両エンジンと TLC で確認し、残高0に到達した。TLC の `Scope` も成立した。Rust・Go・TypeScript の生成コードは正常な Nat を読み、負の Nat を拒否した。MoonBit の生成コードは JS ターゲットで型検査した。

処理前の検証は、JSON の型と数値範囲、設定の事実、初期条件、先行操作、現在のガード、遷移先の範囲と不変条件を確認する。Rust の `dispatch` はその後に実装を呼び、返された受付と状態を照合する。型エラー・範囲外・ガード偽・不変条件違反ではコールバックが実行されない。応答の不一致後はセッションを使えない。

`rcheck validate` は同じ検証を実装の実行なしに再生する。初期残高3から `withdraw(2)` の先行操作を与えると、`withdraw(1)` の予測状態は残高0、`withdraw(2)` はガード偽になる。処理を呼ぶ側が実装と同じ先行操作列を渡す。セッションは有限の参照評価器の対応範囲を使う。

0114 の外部検査の再実行では、出金・選挙・ACL と対照の29判定が維持された。整数幅の対照は、検査器を実行する前に拒否された。型と処理前の対照は `just rcheck-validation`、自然言語のリンクと主張は `just rmodel-design-check` で再確認できる。
