# 0120 要件の節を名前付きの検査へ結ぶ

0119 の節ごとのリンクを `rspec` の `ClauseRule` と `just clause-report` に接続した。既存の要件 ID に、要件内の節 ID、日英の文、名前付きの claim、任意のレビュー版を持たせた。発送の節は rmodel に名前付きの `StaysShipped`、`KeepsTracking`、`ConfirmCourier`、`ConfirmPost` を持つ。既存の `ShippedStays` も残し、正常版と二つの故障で、二つの遷移の性質の連言と判定が一致することを調べた。 [計画](../plans/0120-reviewed-clauses.md) · [試作 0119](0119-requirement-links.md) · [発送仕様](../../spec/rmodel-design.pkl)

| 節                | 名前付きの検査   | 参照評価器の結果 |
| ----------------- | ---------------- | ---------------- |
| `status`          | `StaysShipped`   | 成立             |
| `tracking`        | `KeepsTracking`  | 成立             |
| `confirm-courier` | `ConfirmCourier` | 2操作で到達      |
| `confirm-post`    | `ConfirmPost`    | 2操作で到達      |

CLI は先頭に注意が必要な節 ID を出し、その後に参照の有無・対応レビュー・現行モデルの判定を出す。発送仕様には試作中の結果としてすべて未レビューで入れた。レビュー後は検査した組の `revision` を Pkl の `reviewed` に記録できる。レビュー版は節の文、要件の共通文と用語、対応する式、期待する判定、モデルの宣言・事実・スコープから計算する。モデルの操作や初期化を含めた挙動の判定は CLI を動かすたびに取り直す。版識別子は現時点の rmodel の型付き AST 表現に依存する。

| 対照                                                 | 結果                                                                                                                    |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 現行の版を記録したテスト用 Pkl                       | 注意が必要な節は0件。                                                                                                   |
| `tracking` の文だけを「確認時は変えてよい」に変更    | `tracking` だけ要再確認。モデルの式は成立。                                                                             |
| `KeepsTracking` の帰結だけを弱める                   | `tracking` だけ要再確認。式は成立。                                                                                     |
| `KeepsTracking` の名前を変更する                     | `tracking` の参照は無効でモデル判定なし。他の節は報告される。                                                           |
| 確認のガードを Post に絞る                           | 対応レビューは現行。維持の検査は成立し、`confirm-courier` だけ不達。                                                    |
| コメントを追加、探索予算を使い切る、初期状態をなくす | コメントだけではレビューも判定も変わらない。予算切れは `unknown`、初期状態なしは `empty` となり、全該当節に注意を出す。 |

版の更新は確認の必要な箇所を示す。文章と式の意味の判断はレビューで行う。確認の二つの到達例は、この発送モデルで可能な経路を要求として残す。 [rspec のテスト](../../crates/rspec/tests/clauses.rs)
