# 0114 rmodel はどこまで共通の核にできるか

rmodel は**有限の状態と名前付き操作、状態不変条件、到達可能性**を共通に記述する核として使える。分散システムの仕様や他言語のモデルを広く受け入れるには、順序や重複を持つ値、進行性の契約、検査器ごとの数値と探索の意味が足りない。[事前に固定した条件](../plans/0114-rmodel-portability.md)

## 実行で確かめた範囲

| 対象                         | 実測                                                                                                                                                                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 出金と残高を壊す対照         | 初期残高2・整数0〜4。参照評価器・rtlc・TLCで、正常版の残高保持が成立し、対照は2遷移で違反。Rust・TypeScript・Go の独立実装で境界6組を再生。SAT と Alloy は整数・record が対象外。                                                                                          |
| Raft と二重投票を許す対照    | 3ノード・単一任期。参照評価器・rtlc・TLC・ralloy・Alloy Analyzer で正常版の選挙安全性と当選／票割れの到達を照合。対照の二重当選は6遷移で検出。SAT と Alloy は8 steps の範囲。                                                                                              |
| ACL                          | 権限と秘密文書の例で、独立した JVM ツールを含む全経路が一致。秘密文書の正当な閲覧と、許可のないユーザーからの閲覧不能を区別。                                                                                                                                              |
| 空の初期状態と整数の範囲逸脱 | 初期状態が空なら参照評価器と rtlc は `empty`。TLC の stdout は成功文言と探索0件を両方含む。SAT の到達クエリは空と有界の未到達を区別できない。範囲逸脱では TLC の `Scope` が違反を検出し、参照評価器と rtlc は否定的な判定を `unknown` にする。既に見つかった到達例は残る。 |
| 外部言語からの入力           | Pkl の独立した変換を再生成し、対応する4題材・12件の観測で判定と深さが一致した。二つの人工故障を検出した。ペイロードを持つ order は対象外で、service の活性は変換で欠落する。Quint には別経路の `rquint → TLA+` があり、Quint から rmodel IR へのアダプタは未実装。         |

上の有限モデル7件の29判定では、元の rmodel と IR 入力の参照評価器、rtlc で結果が一致した。Rust の IR テストは、分割された出金と Raft を含め、型検査後に JSON の木へ戻ることも検査する。外部ツールの比較は判定を中心に行い、外部の全遷移や反例形式の往復は未測定。TLC は取り込んだ JAR の表示で `2026.11.15.002146 (bc1b506)`。ファイル名は既存の `0068-tlc-1.8.0.jar`。SAT の境界はループを含む。[Alloy 6 の steps の定義](https://alloytools.org/alloy6.html)

## 検出した不整合

- **修正済み。** rtlc の負の判定は内部の `Scope` が成立すると再帰して停止しなかった。今回の出金正常版で15秒超を再現し、修正後は不変条件の成立を返す。範囲から出る対照は引き続き `unknown`。外部比較用の exporter も、Alloy の非対応を検出した場合は Alloy 出力を省き、TLA+ を生成するようにした。
- **修正済み。** 遷移の欠落を `omitted` に記録した IR を CLI が検査し、対象を縮めたモデルで `holds / complete` と出していた。CLI は欠落を診断して終了する。アダプタの対照テストでは、観測対象を限定した射影を明示して比較する。
- **修正済み。** JSON IR からは、表の構文で拒否する範囲を指定できた。IR でも、個体数1〜7、steps 1〜32、整数が連続20個以内という上限を検査する。
- **未解決。** `Int` の算術について参照評価器は64ビット飽和演算を使う。上限 `9223372036854775807` の値を1増やすモデルを `holds` と判定したが、rtlc は入力を拒否し、TLC は整数を扱えないとエラーを返した。有限列挙範囲と算術の定義域は別の契約にする必要がある。[参照評価器の算術](../../crates/rmodel/src/reference.rs#L248)

## 次の採用判断に必要な表現

- **型と値。** `record` と単純な enum は生成に使える。異なる二つの record に `units` を置くだけで重複名として拒否された。値を伴う variant と、順序・重複を保持する有限列、三項関係の直接表現もない。Raft ログを固定スロットと二項写像に展開する形は、位置・追加の意味・生成する観測型を別途規約化する必要がある。この符号化の意味保存は未測定。
- **進行性。** 時相の問いと弱公平性を入れる形は表の構文と IR の両方で拒否された。TLC の別モデルでは、待機可能な同じ遷移系で `<>delivered` は公平性なしでは反例があり、配信への弱公平性の下では成立した。rmodel の `reachable` は、この二つを区別するための問いを持たない。[TLA+ の安全性・進行性・公平性](https://lamport.org/tla/safety-liveness.pdf)
- **移植の契約。** IR v1 は型付きの遷移契約というより、再型検査する構文木。Quint の List や payload 付き variant などは、rmodel に構文上落とせない場合がある。移植の確認には、使った機能、対応範囲、検査結果、反例の具体的な観測を個別に比較する必要がある。[Quint の言語仕様](https://quint.sh/docs/lang)

次の設計では、先に整数演算の境界契約を決める。次に有限の列と値を伴う variant を、出金の結果型と2任期のログ付き選挙で検証する。公平性・時相の義務は独立にモデル化し、TLC で確かめた配信の正負対照を持ち込む。各段階で、アダプタの IR 往復だけでなく、同じ観測と反例を再生できるかを採用条件にする。

`just rmodel-portability .artifacts/0114-recheck` は新規ディレクトリに入力・生成物・生ログ・`matrix.json` を出す。外部バイナリは `just` の引数で指定する。IR・バインディング経路は `just rcheck-adapters`、`just rcheck-boundaries`、`just rcheck-go` で再実行できる。
