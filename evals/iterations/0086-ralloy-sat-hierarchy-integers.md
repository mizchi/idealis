# 0086: SAT backendでsigの階層と整数を扱う

[plan](../plans/0086-ralloy-sat-hierarchy-integers.md)のとおり、0085のSAT backendを、sigの階層（`extends`・`in`・`abstract`）と整数式へ広げた。

- **範囲**: `div`と`rem`を含むモデル以外は、SATで解けるようになった。
- **正しさ**: SATと総当たりの差分テストは、174 commandのうち166を照合して一致した。対象外は`arithmetic.als`の7と、総当たりが予算内に解けない`CompositionHolds`の1。
- **速度**: `core`はすべて総当たりのまま。0086も追記の0086aも`hold`だが、超えたケースと組の向きが2回で入れ替わった（後述）。

## 変更

- 階層:
  - 子とsubset sigは、親のatomごとの所属の変数で、親への所属を含意する。
  - `extends`の兄弟はatomごとに高々1つ。abstractの親で子があれば、子のいずれかに属する。
  - 子の数は加算回路で数え、commandのscopeの上限以下（exactlyなら等しい）にする。
- 整数:
  - commandのbit幅のbitベクトル（2の補数）。bit幅を固定した加算・減算・乗算・符号反転は、そのまま桁あふれするので、総当たりの値の意味（0082）と一致する。
  - `#e`は真のtupleの数をbit幅で足したもの。Int型の単項の関係は、含むInt atomの値の和。
  - 比較は符号付き（符号bitを反転した符号なしの比較）。
- `div`と`rem`は総当たりのまま。総当たりは0による割り算を`unknown`にするが、SATではその条件付きの結果を再現できない。
- instanceのatom名は、atomが属する最も具体的な`extends`のsig。

## 正しさ

- bitベクトルの単体テスト: bit幅1〜4の全入力の組で、加算・減算・乗算・符号反転・比較・等価・数え上げ・上限・一致が、総当たりの`wrap`と同じ値になった。
- SATと総当たりの差分テストは、166 commandを照合し、111件のinstanceが`check_instance`を通った。テストの下限は、この数を見てから150/90に上げた。
- 5 group（`hierarchy`に`child-bounds.als`の4 commandを加え、178 command）の再生がAlloyと一致した。

人工故障は4件で、最初は2件だけを検出した。

| 故障                                | 最初の結果               | 最終                   |
| ----------------------------------- | ------------------------ | ---------------------- |
| `extends`の兄弟の重なりの制約を外す | 検出                     | 検出                   |
| 符号付き比較を符号なしにする        | 無効（下記）             | 検出                   |
| 加算の繰り上がりを捨てる            | 無効（下記）             | 検出                   |
| 子の数の上限を外す                  | 無効（下記）→ 検出されず | 検出（モデルを追加後） |

最初の検査の途中で、外部の`rustup update`がrustcを1.100.0へ更新していた。そのためrustcが起動できず、3件はテストが走らないまま「検出されず」と判定されていた。判定の条件を「テストが走ったこと」を含むように直してやり直した。

「子の数の上限を外す」故障は、やり直した後も検出されなかった。corpusに、親より小さくexactlyでない子のscopeがなかったため。これを見てから`hierarchy/child-bounds.als`（4 command、Alloyの答えは解あり2・解なし2）を加えて記録し直し、検出した。結果を見てcorpusを足したことは、ここに残す。

Rust・TS・Chromium・`just check`・`wasm-test`・`package`・`evaluate`・`replay-evaluation`が通った。

## 速度

コンパイラの違いが比較に混ざらないよう、結果を見る前にbaselineを差し替えた。planでは0085で保存したbinaryを使う予定だった。代わりに、0085の版（f1b2c20f7）をrustc 1.100.0でビルドし直したbinaryにした。

| 比較                                                 | 開発組で超えたケース                                                                     | 確認組で超えたケース                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| [0086](../runs/0086-ralloy-comparison/result.json)   | `iff-implies` 1.197、`sig-multiplicity` 1.132、`set-algebra` 1.123、`multiplicity` 1.116 | なし（0.853〜0.989）                                                   |
| [0086a](../runs/0086a-ralloy-comparison/result.json) | なし（0.968〜1.085）                                                                     | `cardinality-formulas` 1.112、`dense-graph` 1.112、`dag-closure` 1.105 |

`core`は13ケースすべてが総当たりのままで、0086は総当たりの経路を変えていない。超えたケースは2回で入れ替わり、超えた組も逆になった。負荷平均は4.2〜8.5で、Chrome、IME、WindowServerが動いていた。planに従い、どちらも`hold`として記録し、さらに再測定しない。

Wasmは、同じrustc 1.100.0で比べて556,675 bytesから578,403 bytes（+3.9%）。

## 残り

- `div`・`rem`のSAT符号化（0による割り算を`unknown`として扱う方法が要る）。
- SATへの切り替えの境界（24 bit）は、0087で測って決め直す。
