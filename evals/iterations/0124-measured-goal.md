# 0124 実測から採用のゴール証拠を作る

`rprob` の 3×4 の辺探索の release バイナリとモデル入力を SHA-256 で固定し、同じバイナリの参照評価器と比較した。候補 ID は計測するバイナリの SHA-256。両方式で判定と最短深さが一致し、12操作で全ての辺が揃うことを測定前に確かめる。prepared モードで一プロセス4評価、ウォームアップ1回、各5標本。改善幅10%、標本の幅が中央値の20%以下という基準を測定前の計画に保存した。 [事前計画](../plans/0124-measured-goal.md) · [測定の自己モデル](../../spec/models/measurement-gate.model)

| 実行              | 参照評価器 | rprob   | 発行されたゴール判定                                                                          |
| ----------------- | ---------- | ------- | --------------------------------------------------------------------------------------------- |
| 初回              | 482.7 ms   | 9.8 ms  | 未測定。Python 3.9 で `zip(strict=True)` が使えず、集計できなかった。                         |
| Python 3.9 対応後 | 480.5 ms   | 10.5 ms | 未測定。rprob の標本の幅が中央値の20%を超えた。                                               |
| 同じ方針で再計測  | 480.1 ms   | 11.2 ms | 改善。平均で約43倍。両方式の標本が安定し、候補の最大値も比較元の最小値より10%以上小さかった。 |

各時間は一プロセス4評価の壁時計の平均。採用された測定とノイズで未測定となった測定は、保存した計画・結果・ハッシュから再生して同じ判定を得た。 [初回](../runs/0124-measured-goal/initial/goal-evidence.json) · [未測定対照](../runs/0124-measured-goal/noisy/goal.json) · [改善の生データ](../runs/0124-measured-goal/confirmed/goal.json)

`RMODEL-MEASURED-IMPROVEMENT` の自己モデルでは、計画の一致・安定した標本・改善幅の三つが揃うと4操作で改善を発行できた。どれか一つを外す人工故障は、それぞれ3操作で対応する不変条件に違反した。参照評価器と rprob は判定・深さとも一致した。集計器のテストでは別計画、別モード、異常終了、標本不足でも改善を出さないことを確かめた。 [モデルと故障のテスト](../../crates/rprob/tests/reference.rs) · [集計器のテスト](../experiments/rprob/test_goal.py)

同じ候補版について、実行した二検査器の比較と、記録した実測の改善を採用コマンドに渡した。現行の仕様では対応レビューの未完了だけが残った。テスト用のコピーに対応レビューの版を明示的に記録すると採用可能になり、同じコピーでもノイズの大きい測定を渡すとゴール改善が確認できず採用を保留した。 [実行手順](../../crates/rspec/README.md#evidence-for-adoption)
