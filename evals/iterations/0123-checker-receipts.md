# 0123 検査結果から採用の意味比較を作る

`RMODEL-EXPECTED-CHECKERS` は、予定した二つの検査器が同じ版で探索を完了して判定が一致した場合に、意味の一致を発行できると定める。実装では候補・要件・モデル入力の SHA-256・探索予算を計画に記録する。別々のコマンドで参照評価器と rprob を実行し、判定・最短深さ・宣言とスコープの判定・操作の到達を照合する。比較はリンクされた一つのモデルを対象とする。 [計画](../plans/0123-checker-receipts.md) · [モデル](../../spec/models/checker-comparison.model) · [コマンド](../../crates/rspec/README.md#evidence-for-adoption)

| 対照                                               | 結果                                                                  |
| -------------------------------------------------- | --------------------------------------------------------------------- |
| 現行計画の両方の結果が一致                         | `equivalent` を発行。現行版のレビューとゴール改善を加えると採用可能。 |
| 一方だけ、または他の候補版・探索予算から片方を流用 | `missing`。同じ検査器の同一結果を重複して受け取っても不足。           |
| 予算切れ・対応外                                   | `incomplete`。                                                        |
| 両方の初期状態が空                                 | `empty`。                                                             |
| 確定した判定が異なる                               | `diverges`。                                                          |
| 同一計画・同一検査器から矛盾する結果が再送される   | `incomplete`。                                                        |
| モデル入力を計画作成後に変更                       | 実行前にエラー。                                                      |

モデルは二版・二検査器・二種類の抽象結果を扱う。現行版の一致に4操作で到達した。一方だけで発行できるようにすると2操作、旧版の完了を流用できるようにすると4操作、相異なる結果を許すと3操作で、それぞれ対応する不変条件に違反した。正常と故障の判定および最短深さは、参照評価器と rprob が一致した。再送の衝突処理は実装テストで検査した。 [モデルの差分テスト](../../crates/rprob/tests/reference.rs) · [結果から採用までのテスト](../../crates/rspec/tests/comparison.rs)

## SpecEngineeringBench をどう使うか

論文の試験入力は、Python リポジトリと要求文で、バグの説明や対象ファイルのヒントは与えない。正常側で走るテストを数える Head Pass Rate と、故障側で落ちて修正版で通るテストを数える Fail-to-Pass Rate を分けている。100課題・7エージェントの報告では、Head Pass Rate 91.47%、変更行へのカバレッジ80.48%、Fail-to-Pass Rate 26.36%。後者は故障を識別したテストの割合であり、発見したバグの割合とは定義が異なる。 [SpecEngineeringBench §§2.1–2.2、3.2](https://arxiv.org/pdf/2611.32973)

今回の期待値は両検査器の出力を見て決める前に、現行版・両結果・一致という要件から固定した。正常版を通すことと、この条件を一つずつ取り除いた人工故障を識別することを測った。検査器の一致が仕様の妥当性まで示すかを評価するには、仕様の例と反例を独立に置く必要がある。今回の結果は既知の人工故障への感度を示す。未知の実バグの発見率は未測定。 [事前計画](../plans/0123-checker-receipts.md)
