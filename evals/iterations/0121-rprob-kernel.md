# 0121 有限集合モデルの探索カーネル

rmodel の型検査済み AST から、集合を atom のビット列、二項関係を 8×8 のビット行列に変換する `rprob` を実装した。操作の引数と有限量化を事前展開し、式の名前をスロット番号に解決する。幅優先探索では次状態用の配列を再利用し、初めて見た状態だけを確保する。参照評価器と同じ予算単位で、構成・初期候補・到達状態を数える。 [計画](../plans/0121-rprob-kernel.md) · [カーネル](../../crates/rprob/src/lib.rs) · [変換](../../crates/rprob/src/compile.rs)

権限・セッション・排他・3ノードの Raft 選挙・二項関係の合成・和 sort・辺探索・関係で表した発送を参照評価器と比較した。複数の予算で、性質の判定、最短深さ、宣言違反、操作の到達が一致した。発送の正常版では Courier と Post とも2操作で確認済みに到達した。追跡方法を上書きする故障は2操作で検出し、Courier の確認だけを止めると追跡方法の維持は成立して Courier の確認済み状態は不達になった。空と予算切れも区別した。関係で表した発送の正常版は rtlc とも判定が一致した。 [回帰テスト](../../crates/rprob/tests/reference.rs) · [発送のモデル](../../fixtures/rprob/shipment.model)

## 計測

Apple M5、macOS 26.6.2、Hyperfine 2.0.0。両エンジンを同じ release バイナリに含め、比較前に全出力が一致することを確認した。時間は一プロセスで同じモデルを所定回数評価した合計の平均 ± 標準偏差。権限は3回、3×4は4回、4×4は1回。一方の方式ごとに1回ウォームアップし、権限と3×4を7標本、4×4を5標本計測した。

| モデルと方式                  | 参照評価器         | rprob           | 速度比 |
| ----------------------------- | ------------------ | --------------- | ------ |
| 権限、毎回パース・準備        | 325.63 ± 6.68 ms   | 12.06 ± 0.08 ms | 27.0倍 |
| 権限、準備再利用              | 340.93 ± 27.51 ms  | 12.18 ± 0.31 ms | 28.0倍 |
| 二項関係3×4、毎回パース・準備 | 498.82 ± 44.98 ms  | 9.84 ± 0.10 ms  | 50.7倍 |
| 二項関係3×4、準備再利用       | 478.82 ± 6.21 ms   | 9.72 ± 0.10 ms  | 49.3倍 |
| 二項関係4×4、準備再利用       | 3166.15 ± 39.14 ms | 45.99 ± 0.61 ms | 68.8倍 |

4×4は16本の辺が独立に変わる65,536状態のモデル。ピーク RSS の平均は123.85 MiB → 9.40 MiB、命令数の平均は85.36×10⁹ → 0.99×10⁹。準備再利用の参照側はパース済み AST を渡す現行 API、rprob 側は一度変換した `Compiled` を使う。計測は準備の差も含む。比較相手は rmodel の参照評価器。 [権限の集計](../runs/0121-rprob-kernel/permissions.json) · [3×4](../runs/0121-rprob-kernel/edges-3x4.json) · [4×4](../runs/0121-rprob-kernel/edges-4x4.json)

`just rprob-test` で差分テスト、`just rprob-bench .artifacts/rprob-new` で再計測できる。対応範囲は有限 atom の集合・二項関係で、構造化された値と時相の問いは変換時に対応外を返す。 [対応範囲](../../crates/rprob/SUPPORT.md)
