# 0099: sortの静的な型検査と、多重度の違反の報告

[plan](../plans/0099-sorts-and-violations.md)のとおり、rmodelの型検査をarityからsortへ広げ、多重度を破る遷移を、起きない遷移ではなく報告する違反にした。参照評価器と2つの写し方（Alloy・TLA+）、生成器、読みやすさの評価のすべてに入れた。意味論は[docs/kernel-semantics.md](../../docs/kernel-semantics.md)に反映した。

- **型**: 和・差・積・比較は両辺が同じsort、joinは繋ぐsortが同じ、代入は変数と同じ型。corpus（`fixtures/rmodel`・`spec/models`）はすべて型が合った。sortの違う集合の和を使っていた既存のテスト2件は、型の合う書き方に直した。集合が1つのsortに収まるので、`#`の値はsortの大きさ（最大7）を超えない。
- **多重度の違反**: 組み込みのcheck `Declarations`で報告する。違反した状態からは遷移せず、checkは違反していない状態でだけ評価する。TLA+は`TypeOK`を前提に遷移し、違反した状態は止まる（`TypeOK => 式`）。Alloyはvar fieldの多重度を式にし、違反した状態はstutterする。
- **Alloy・TLCの記録**: rmodelのcorpusの20 checkで、Alloy 6.2.0とTLCの答えを記録し直した。判定は前と同じ。

0098のdev（36/42）とはモデルが違うので、差は参考にとどめる。誤答5件の分類:

- **sortの合わない式**: 0件（型検査で書けなくなった）。
- **多重度を状態の制約として使っていない（3件）**: 2006の`Inv`・`a2`、2007の`a1`。`// exactly one element`の注記がある変数を、推論で1要素として扱っていなかった。2006の`Inv`は、違反した状態をcheckの対象と読んだ可能性もある。
- **段階の多い推論の誤り（2件）**: 2005の`Inv`・`Goal`。

次の仮説: 多重度をコメントの注記ではなく型で表す（`A -> Option[B]`・`A -> B`・`NonEmptySet[A]`など）と、状態の制約として読まれる。新しいdevの問いで試す。
