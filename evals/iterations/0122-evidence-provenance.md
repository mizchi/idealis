# 0122 自己仕様の採用判断と証拠の版

従来の採用判断は、意味の一致とゴールの改善を候補の外から受け取っていた。二候補版のモデルを追加し、節レビューの完了・意味の一致・ゴール改善を、それぞれ証拠が得られた版に結び付けた。自己仕様の `RMODEL-EVIDENCE-PROVENANCE` は三つの条件を名前付きの検査に結び、`rspec::assess_adoption` と実装テストへの参照も持つ。 [計画](../plans/0122-evidence-provenance.md) · [モデル](../../spec/models/evidence-adoption.model) · [仕様](../../spec/rmodel-design.pkl)

## モデルでの照合

| ケース                                       | rmodel 参照評価器と rprob の結果                    |
| -------------------------------------------- | --------------------------------------------------- |
| 旧版の意味の一致が改版後に届く               | 2操作で到達                                         |
| 現行版の三つの証拠が揃う                     | 新版の採用に5操作で到達                             |
| 旧版の一致でも採用できるようにガードを弱める | 現行版の意味の一致が必要という不変条件に5操作で違反 |

二つの版と肯定的な証拠を持つ有限モデルを用いた。新しい版への移行は一度。比較の未完了などは肯定的な証拠がない状態に対応し、実装側では結果を個別の値として扱う。 [差分テスト](../../crates/rprob/tests/reference.rs)

## 採用判断の入力

評価を依頼した時点に、候補 ID、要件 ID、評価版を記録する。評価版は、節の文と式の対応に加えて、リンク先モデルの操作や初期条件も含む。節の対応レビューの版と、評価結果を受け取る版を独立して扱う。ガードだけを変えると節の版が一致しても、変更前に集めた検査結果は失効する。

`just adoption-evidence --pin CANDIDATE` で依頼時の版を取得し、`--assess CANDIDATE COMPARISON.json GOAL.json` で現行版の節レポートと合わせて判定する。比較とゴールの測定結果は、評価した時点の版を含む外部入力とする。検査では、旧い候補、同じ候補 ID でモデルだけ変更、未レビュー、予算切れ、不一致、空、未完了、結果の欠落、ゴール悪化を採用から除いた。正の対照では同じ版で三つを満たすと採用可能になった。初版8通り・新版27通りについて、証拠の到着状態と版を変え、実装の判定が rmodel の採用ガードと一致することも確認した。 [使い方](../../crates/rspec/README.md#evidence-for-adoption) · [実装テスト](../../crates/rspec/tests/adoption.rs)
