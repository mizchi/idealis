# 0087: SATと総当たりの切り替えの境界

[plan](../plans/0087-ralloy-backend-threshold.md)のとおり、SATで扱えるcorpusの171 commandについて、両backendの時間を測った。

- **境界の選び方**: 全commandの時間の合計が最小になる境界は4 bitで、24 bitの約18分の1だった（3.88 ms対68.31 ms）。確認runでも4 bitが最小だった。
- **`core`の速度**: 4 bitでは、総当たりで数µsで解けていたcommandが2〜13倍遅くなり、`hold`。境界は24 bitに戻した。
- **分かったこと**: 幅は、どちらのbackendが速いかの目安にならない。

## 測定

[開発](../runs/0087-ralloy-backends-development/result.json)と[確認](../runs/0087-ralloy-backends-confirmation/result.json)のrun。各commandをwork予算5000万で両backendで解き、1回あたりの中央値を取った。両backendのstatusは、総当たりが予算切れになる1件（`CompositionHolds`）を除いて、すべて一致した。

[境界ごとの合計](../runs/0087-ralloy-threshold/result.json)（ms）:

|      境界（bit） |   開発 |   確認 |
| ---------------: | -----: | -----: |
|                0 |   4.09 |   4.02 |
|                4 |   3.88 |   3.81 |
|                8 |   4.22 |   4.15 |
|               12 |   8.98 |   8.96 |
|               16 |  34.90 |  34.82 |
|           20・24 |  68.31 |  69.66 |
| 28以上・使わない | 無限大 | 無限大 |

28以上で無限大なのは、`CompositionHolds`（幅27）を総当たりで解くと予算切れになるため。保存したresult.jsonでは、無限大がJSONの`null`として書かれている。境界の選択はメモリ上の無限大で計算しており、結果は正しい。runは上書きしないので、ここに記録する。

## `core`の速度

[比較](../runs/0087-ralloy-comparison/result.json)。baselineは0086のcandidate（24 bit）、candidateは4 bit。

| ケース              | 開発   | 確認   |
| ------------------- | ------ | ------ |
| `core-set-algebra`  | 0.004  | 0.004  |
| `core-iff-implies`  | 0.524  | 0.153  |
| `core-preds`        | 13.074 | 10.089 |
| `core-graph-cycles` | 8.383  | 7.892  |
| `core-pigeonhole`   | 5.037  | 2.457  |
| `core-dag-closure`  | 2.210  | 2.321  |
| `core-exact-scopes` | 1.167  | 1.240  |

合計は約34 msから1 ms未満になったが、6ケースが閾値1.1を超えて`hold`。境界を24 bitに戻した（revert）。

## 幅が目安にならない理由

同じ幅の中で、SATと総当たりの時間の比が大きく散らばる。幅16では0.001倍から112倍だった。

| 状況                                 | 速いbackend                                             | 例                                                          |
| ------------------------------------ | ------------------------------------------------------- | ----------------------------------------------------------- |
| 解（instanceや反例）がすぐ見つかる   | 総当たり。数µsで終わり、SATは符号化だけで約100 µsかかる | `dense-graph`の`NotConnected`は総当たり1.7 µs、SAT 190.8 µs |
| 解がなく、全体を数え尽くす必要がある | SAT                                                     | `set-algebra`の各check                                      |

幅は探索空間の大きさを表すが、解がすぐ見つかるかどうかは表さない。合計を最小にする選び方は、少数の大きい探索に引っ張られて境界を下げ、小さい探索の後退を許した。

## 次の候補

境界ではなく、両方を組み合わせる方法（portfolio）が考えられる。総当たりを小さいwork予算で先に走らせ、終わらなければ残りの予算でSATへ切り替える。総当たりで速く解けるcommandはそのまま速く、大きい探索はSATに回る。最悪でも、先に使ったwork予算の分だけ遅くなる。
