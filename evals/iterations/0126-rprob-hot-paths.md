# 0126 rprob の探索コストを下げる

4×4の辺探索の `sample` では、スタック先頭で述語評価991標本、項評価797標本、ハッシュ書き込み283標本が見つかった。候補列挙を変えた0125の実装を基準にし、変更を一段ずつ計測した。 [計画](../plans/0126-rprob-hot-paths.md) · [プロファイル](../runs/0126-rprob-hot-paths/dense-profile-top.txt)

| 段階                   | 選択と観測                                                                                                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 単一スロットの状態保存 | 一語をFIFOに直接入れる。最大16 tupleでビットマップのワード数分の予算があれば、穴のあるビット位置を詰めて既訪問を記録する。上限は8 KiB。密な辺探索では命令数22%減、ピークRSS 73%減。2スロットの命令数は4.7%増えた。    |
| 式の特殊化             | 展開時に判明する定数を使い、集合演算をマスク、単一 atom の像を行の切り出し、定数との比較をマスク付き等値判定に変換する。密な辺探索では、この段だけで命令数33%減。                                                     |
| 候補走査               | 連続する単項ビットはシフトで復元し、二項の各行は繰り上がりで進める。6×6全関数で命令数25%減。壁時計の標本に外れ値があり、この段の壁時計の平均では悪化した。                                                            |
| 2スロットの状態保存    | 2語をFIFOと既訪問集合へ直接入れ、状態ごとのヒープ確保を省く。この段の2スロットモデルで命令数13%減、ピークRSS 14%減。                                                                                                  |
| 構成ごとのガード評価   | 状態を読まないガードは構成ごとに評価し、状態探索では判定を再利用する。権限モデルで命令数11%減。密な辺探索の命令数は約1%増えた。                                                                                       |
| 遷移の書き込み         | `set` の多重度検査を即時に通し、全スロット代入時は前状態のコピーを省く。初期候補の検査で予算を使い切った場合は操作の準備を省く。密な辺探索では命令数8.9%減。疎な集合と6×6全関数では命令数がそれぞれ2.5%、3.0%増えた。 |

同一のmacOS arm64上で、同じreleaseハーネスの変更前と最終版を比較した。ウォームアップ1回、各5標本の平均。準備再利用では一つのプロセスで表に示した回数だけ探索する。 [全段階の集計・判定・SHA-256](../runs/0126-rprob-hot-paths/)

| 集合4領域、予算1、都度準備  |            1.19 → 1.23 |              1.92 → 1.93 |

各段の測定前に全負荷で判定全文の一致を確認した。参照評価器との比較では、非連続のビット位置、2スロットの組、予算不足でハッシュ方式を選ぶ経路を検査した。同じ状態へ戻る操作の遷移性質、予算が切れて状態を評価する前の操作到達、同時代入と部分代入も確認した。最終版の4×4の辺探索は参照評価器とも判定全文が一致した。 [回帰テスト](../../crates/rprob/tests/reference.rs)

`just rprob-hot-path-bench <新しい出力先> <変更前のreleaseバイナリ>` で再計測できる。変更前と各段のバイナリは `.artifacts/0126/` に保存した。5段目終了時の `target/release/rprob-benchmark` は `rprob-before-updates` に退避している。ソースは作業ツリーからビルドしたため、記録したHEAD単体から各段のバイナリは作れない。3スロット以上では共有スナップショットを使う。今回の評価は明示探索の範囲で行い、有限領域の上限や予算単位は同じ。都度準備・予算1の結果は差が0.04 msで、全体の短縮は主に探索を実行する負荷で見られた。
