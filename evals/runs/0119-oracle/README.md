# 0119-oracle

The observation-only copy of the "before" source (the plan's origin/main, 42b88c5a9): the non-recursive dynamic-evaluation limit is 4,096 instead of 128 (`oracle.patch`; the recursive limit of 128 stays), `evaluation_depth` is a u16, and a function records the largest depth that `descend` compared with its limit (the value before the increment, including the leaf check that calls `descend` from depth 128). It is built with the same commands as "before" and never used outside this evaluation. `snapshot-oracle.sha256` holds the sha256 of its binaries, built from this final source (`oracle-r2`). The first Wasm measurements (used for the decision on the value, see `../0119-audit/README.md`) were taken with an earlier build of the same behaviour, before the recording line moved; `../0119-wasm-ceiling/` holds the rerun with `oracle-r2`.

A limit L rejects an input whose recorded depth is L or more. For inputs that end in an expression leaf (hop, call, operator, ...) the recorded depth is the plan's 5 + 3N. For inputs that end in a step visit (ENABLED steps, binder locals, temporal calls, action steps) the structural depth can be one larger and is still accepted. The stack harness prints the record as `peak=` when it is built with the cargo feature `oracle-peak`.

- `boundaries-255.json`: for each of the 13 kinds of `crates/rtlc/tests/stack_programs`, the largest size whose recorded depth is at most 255 and the next size, with the oracle's output (these are the sizes of `crates/rtlc/tests/evaluation_stack.rs` at the limit 256). `boundaries-511.json` is the same for 511 (the first value, superseded). `depth-cap{125,250,500}.json` give the sizes used for the stack measurements.
- `baseline-{before,oracle}-0119-r4.json`: outputs of `evals/experiments/call-depth/baseline.ts` for the final 0119 inputs. `fixtures/call-depth/records-0119.json` holds this pair, and `cases-0119.json` is derived from it by `expectations-0119.ts`. `-r3` used the input list before the recursive input and the `UNCHANGED Vn` depths were corrected, and `-r2-512-inputs` used the list of the first value (512); both are superseded.

The comparison of after with this copy is in `../0119-paths/analysis.txt`.
