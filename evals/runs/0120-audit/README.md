# 0120-audit

Audit record of the evaluation stage of iteration 0120 (plan `0120-forwarding-depth`, r5). File contents are the evaluator's originals with host-specific paths and names replaced by placeholders (`<scratch>`, `<after>`, `<before>`, `<oracle>`, `<oracle-after>`, `<mise>`, `<home>`, `<user>`). Binaries, tool installs, build outputs and the build logs of dependencies are not copied. The plan names one run per measurement (`0120-tlc`, `0120-oracle`, `0120-paths`, ...); this record keeps them as sub-directories of one audit run, as `0119-audit` did.

Trees: `<before>` is `git archive` of b57c0a376 plus the new `crates/rtlc/tests/stack_programs/mod.rs` and the stack harness (`crates/*/src` unchanged, see `checks/protected-*.txt`). `<after>` is the worktree (it is never modified by the evaluation). `<oracle>` is `<before>` with `evals/experiments/call-depth/oracle-0120.patch`, `<oracle-after>` is a copy of `<after>` with `evals/experiments/call-depth/oracle-0120-after.patch` (the plan names one patch; the two trees differ in `descend`, so the same change is two patch files, made by `evals/experiments/call-depth/audit-0120/make-oracle.py`). Builds of different trees never shared a cargo target directory after the first probe builds went stale (see `build-probe-r1-*` below); the `Compiling rtlc (...)` line of each build log names the tree it compiled.

`commands.tsv` lists every command with start, end, load, exit, outcome (`ok`, `failed`, `rss-cap`, `timeout`, `disk-floor`), peak RSS of the process tree (1 s polling at first, 0.25 s after the first runs) and wall seconds. Every measured command ran under `evals/experiments/call-depth/audit-0120/run.py` (RSS cap 4 GiB, wall clock 30 minutes unless a row gives another limit, disk floor 30 GiB). No command exceeded a cap. A command shorter than one polling interval shows `peak_rss_kib=0`. Measurements ran one at a time.

## Held steps (second stage)

These steps were held until the formal-tool slot was free. They ran serially, each under `run.py`, with the process check (`pgrep` for `run-expected.ts`, TLC, `idealis-core`, quint and apalache) before each step and the 30 GiB disk floor. Summaries are under `paths/`, `tlc/`, `evaluator-corpus/`, `temporal/`, `kernel/` and `suite/`; raw outputs are under `target/0120-audit-raw/` (digests in `reduced.json`, `heldSteps`).

- **4-path rerun** (`paths/analysis.txt`, `paths/differences.tsv`, `paths/byte-counts.json`): 410 inputs, 3,280 cells per side, response bytes compared before parsing. hit-0 v2 cells that differ before vs after: 0 (1,110 response comparisons plus 438 compile-error texts); v1 cells that differ from before (after, oracle, oracle-after): 0 of 1,640 each (618 response comparisons, 1,022 compile-error texts); IR sha256 that differ before vs after: 0 of 1,820 cells with an IR. v2 cells whose response changed: 46 (14 inputs), each with hits >= 1 and byte-equal to the `oracle-after` response (46 of 46). `oracle` vs `oracle-after` own responses, hit cells included: 0 differences in 1,202 pairs (1,110 with hit 0, 92 with hit >= 1). The `published256` branch (138 cells: 92 of `oracle` against before, 46 of `oracle-after` against after) is byte-identical to the real response in 138 of 138 cells (the probe of the final round serializes the published reply with the product's own serializer). Raw `program` text of the compile responses: 5,460 comparisons (before against after, `oracle`, `oracle-after`), 0 differences.
- **Scanner check** (`probe-scan-check.mjs`): on real native `oracle` output for `hop-invariant-40`, `hop-invariant-168`, `violation-120`, `division-by-zero-120` and `hop-124`, the probe member was found at the expected offset, the text with it cut out equals the before response byte for byte when hits256 is 0 (1 case, 125 characters), and `published256` was extracted for the four hit cases. The scanner also produced the 1,202 own-response byte equalities and the 46 changed-cell equalities above on all four paths.
- **TLC recount** (`tlc/analysis.txt`, `tlc/verdicts.tsv`): 59 inputs x before/after x rust-native/ts-native. Mismatches where both reach a verdict: 0. Unjudged cases are listed (115 rows; per slice 32, 37, 18, 28).
- **Example C** (`tlc/example-c.txt`): TLC 2.19 rev 5a47802 reports the violation 0 -> 16 with 17 states generated and 17 distinct, the same states, generated count and trace as rtlc after.
- **Existing inputs**: `evaluator-corpus` and `temporal-parity` (`evaluator-corpus/summary.json`, `temporal/summary.json`). Byte scope: `evaluator-corpus` compares the raw `compile-tla` and `check-safety` responses (492 digests, 0 differences); its `check-tla` responses are compared by value only. `temporal-parity` compares values for every response and records 4,680 raw response comparisons of `compile-tla` and `check-tla` requests (not `check-safety`) as a count; the saved result has no per-command digests, so that count cannot be recomputed from the record and is not counted as measured. Byte equality of the complete responses (the plan's condition for existing inputs) is therefore measured for `compile-tla` and `check-safety` only (492 digests); corpus `check-tla` and `temporal-parity` are value-level only, and byte equality there is unmeasured.
- **Recipes** (`suite/summary.md`).
- **Criterion kernel** (`kernel/`): ratios 0.985 to 1.051, 0 of 14 functions at 1.10 or more. Plan r5 requires serial measurement and an ABBA recheck when a regression of 10% or more appears; the run was serial on a shared host (load average 2.6 / 3.9 / 3.3 at the start), no function reached 10%, so no ABBA ran.
