# Souther

Souther 0.5.0 で `bash check.sh` を実行すると、5題材のソースと付属の `*.examples.sou` をまとめてコンパイルする。38件の例がコンパイル時に実行され、5モジュールの JVM クラスが生成された。口座への初回入金の期待値を 3 から 4 に変えると、実値 3 と一致せず E1905 になった。

| 題材        | 検査した内容と制約                                                                                                                                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| permissions | 固定設定の前提と状態の `NoLeak`・`OnlyGranted` を構築時に検査する。`SecretRead` は初期状態からの読取で例証する。`UnclearedSecret` に相当する状態は `NoLeak` により構築時に拒否される。到達状態の全探索は行わない。                                          |
| bank        | `NonNegative` を構築時に検査し、`Rich` を初期状態からの入金1回で例証する。口座の集合は初期化の引数。整数は符号付き64ビットで、加算前に上限を引いた値と比較してオーバーフローを防ぐ。                                                                        |
| order       | `Shipped` と `Cancelled` の payload は網羅的な `match` で取得する。1つの注文が両方の状態を取ることは直和型で排除する。配送済み注文の各操作を拒否する例と、別注文を操作しても同じ追跡情報が残る例を実行した。`FraudCancelled` は初期状態からの例で確認した。 |
| sessions    | `Capacity` と `LockedByAdmin` を構築時に検査する。初期状態から `LockedIsActive` の反例と `Full` の例を実行した。3人目のログインは例で拒否され、3人がアクティブな状態の構築は `Capacity` が拒否する。                                                        |
| service     | `Disjoint` を構築時に検査し、要求してから処理する例を実行した。`EventuallyServed` に必要な無限トレースと弱い公平性は未対応。                                                                                                                                |

遷移は前のスナップショットを受け取り、次の状態か `Disabled` を返す。検査時の atom 数は例の入力で具体化した。CLI はコンパイル時に条件を静的に示せなかった箇所を E2011 として報告し、実行時の構築検査は残す。今回の実行では permissions に1箇所、sessions に3箇所、service に1箇所の警告が出た。例の成功は状態空間全体の証明を表さない。

| rubric                  |  点 | 根拠                                                                                                           |
| ----------------------- | --: | -------------------------------------------------------------------------------------------------------------- |
| identity                | 0.5 | ID は名義型で区別できる。検査器に渡す有限 scope の指定は例の入力で代用する。                                   |
| config                  |   1 | 不変の設定とその前提を `data` と `invariant` で宣言できる。                                                    |
| ints                    | 0.5 | 数値と値オブジェクトを扱える。組み込み `Int` は数学的整数と範囲が異なる。                                      |
| adt                     |   1 | payload 付き直和と網羅的な `match`。                                                                           |
| typeExclusion           |   1 | 同一注文の配送済みと取消済みの併存を直和型で排除する。                                                         |
| step                    |   1 | `behavior`、`guard`、不変スナップショットで遷移を記述できる。                                                  |
| lone                    |   1 | `User?` が0人または1人のロックを表す。                                                                         |
| count                   |   1 | `Set.size` で人数の上限を書ける。                                                                              |
| tree                    | 0.5 | コンパイラ内部に型付き AST と Core IR がある。今回の比較用の AST 出力と idealis IR adapter は作っていない。    |
| verification / liveness |   0 | コンパイル時の型検査と例、構築時の契約検査を使った。比較対象となる状態探索、帰納法、証明、活性の検査は未計測。 |
| codegen                 | 0.5 | JVM バイトコード生成を確認した。                                                                               |
| conformance             |   1 | 同じ `example` を Java 実装へ適用できることが言語仕様にある。今回は Souther 実装への照合を実測した。           |
| enforcement             |   1 | 生成した直和型で相互排他を強制し、生成コードは値の構築時に不変条件を検査する。                                 |

参照は `souther doc ast-tracking`、`souther doc example-pending`、`souther doc invariant-mvp` と、[Souther 公式実装](https://github.com/souther-lang/souther)、[作者による Java 実装との照合の解説](https://zenn.dev/kawasima/articles/souther-ddd-trilemma)。
