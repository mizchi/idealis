## 144入力の評価から進めること

[今回の実測](review.md#144入力での評価) を基準に、文法を変える前に次の試行で詰まる箇所を確認する。

| 優先 | 課題                               | 評価の完了条件                                                                                                                                                                                                                                 |
| ---- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 初見で書き、実装の差分にたどる     | 自動保存の自然言語規則とチートシートを渡す。古い応答を許す対照をモデルで検出し、実装で差分を出し、ITF で同じ差分を再照合できるかを見る。正否、初回検査と再生までの時間、参照先、最初に迷った箇所を記録する。                                   |
| 2    | 検査対象と診断範囲を見つける       | `Scope`、式の内側の未集計分岐、補充モデルの引数一覧の打ち切りを用意する。診断から次に使うコマンドと判定の範囲を選べるか確認する。式の位置を出す試作は、304の内側の枝を外側の枝と区別し、IR と分岐マップでも同じ診断を返すことを確認する。      |
| 3    | 大きい列と部品の再利用を独立に試す | Node.js の入れ子 I/O で64 atom 上限に達する対照を使い、新しい表現と参照検査器の判定・経路を比較する。保存部品は入力の異なる環境でも契約を実行し、入力不足と保証違反を判別する。IR を変更する場合は旧 v1 の保存物と外部検査器の経路も再生する。 |

引数に固定された役割を型に移すと、生成 binding の API が変わり得る。ABA の対照では確認できたため、既存の利用者がいるモデルには API を確認したうえで適用する。時相・値付き variant・短い列の rprob 対応はすでに実例で確認済み。残る課題は値域の拡大と未対応式の切り分け。[rprob の対応範囲](../rprob/SUPPORT.md)

宣言の未参照を調べる場合は、モデル内部の参照と、公開 binding や実装の `derive` 指定も読み取れる範囲を決める。まず対照モデルで両者を区別できる診断を試す。[未参照の対照結果](review.md#到達性と診断の境界)

`Scope` の経路は `capabilities` の `scopeWitness` から見つけられるようになった。変更配信の有限範囲を狭めた対照で3操作目の逸脱を再現し、rprob の列の上限理由も実行時と一致した。優先2では初見の利用者がこの出力から再現まで進めるかを確認する。[対応一覧](../idealis-check/README.md#see-available-checkers-before-searching)

分割ダウンロードの `let status` と、HTTP 304 のレコードフィールドに直接書いた条件を元の位置から引けるようになった。残る対照は、述語内だけで使う束縛と、量化子などで評価が途中で終わる場合の分岐。[設計ログ](grammar-decisions.md#レコードの中に書いた条件を追う)

## 不足している機能

| 機能                   | 困る場面                                                                                                                                                                                                                                                                                                                                                                                               | 確認方法                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大きな有限列を検査する | 短い配送キューの有限経路と公平性付き進行性は照合済み。入れ子の I/O は列リテラルの縮小が効く。自由な復旧キューはスロット内の番号で検査できる。補充モデルの操作引数は予算付きで検査できる。再試行キューの回転では計算で作る大きな列も照合した。番号を使う要素の一時集合も照合した。1ワードに収まる二項関係は行ごとに保存できる。ワードに収まらない関係や、範囲を外れる途中の値を別の型に入れる式が残る。 | 値の表現を広げる場合は既存の小モデルと配信中のキューを照合する。[公平性の照合](grammar-decisions.md#配送とロックの公平な循環を有限グラフで調べる) · [rprob の対応範囲](../rprob/SUPPORT.md) |
